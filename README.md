# Техэтаж

Telegram-бот с мини-приложением для техэтажа общаги: прачечная (стиралки, сушилки, очередь, брони, отметка «внутри вещи, программа не запущена») и календарь броней игровой. Работает на Cloudflare Workers, данные хранятся в D1.

Весь сервер находится в `src/worker.js`. Он принимает вебхук Telegram (`/telegram`), отдаёт страницу приложения (`webapp/index.html`) и обрабатывает её запросы (`/api/state`, `/api/action`). Пользователь проверяется по подписи Telegram. Cron раз в минуту вызывает `tick()`: напоминания, конец программ, брони, обновление закрепов. Запросы приложения вызывают `tick()` только по своему чату и выходят сразу, если делать нечего, поэтому опрос состояния — это три похода в базу. Cron также рассылает личные напоминания: вечером (`ROOM_REMIND_HOUR`) спрашивает про брони игровой на завтра кнопками «Да, бронь нужна» / «Нет, отменить бронь» и напоминает за полчаса до начала. Нажатия кнопок приходят тем же вебхуком как `callback_query`. Таблицы в базе создаются сами, настройки лежат константами в начале файла.

Деплой: `npm install`, `npx wrangler login`, потом `npm run deploy`. Секреты `BOT_TOKEN` и `WEBHOOK_SECRET` задаются в Cloudflare, в репозиторий их не кладём. После деплоя откройте `/setup?key=WEBHOOK_SECRET` — иначе Telegram не будет присылать нажатия кнопок. Тесты в `tests/` работают с фейковым Telegram: запустите `python tests/faketg.py` и `npm run test:server`, затем `npm test` (или `python tests/all.py`). Наборы можно запускать и по одному, в любом порядке: `drive.py` (брони, очередь, время), `done.py` (конец программы, забытые вещи), `room.py` (игровая), `auth.py` (подпись initData, секрет вебхука, права админа), `race.py` (параллельные запросы и перекладывание в выбранную машину), `abuse.py` (лимиты, флуд, размер запросов, /block). Общая обвязка — `common.py`: подписанный initData, вызов вебхука, запуск cron и доступ к базе.

Защита от флуда и нарушителей. Запросы без верной подписи Telegram отсекаются до базы: неверный initData, секрет вебхука или ключ `/setup` стоят только проверки HMAC (сравнение за постоянное время), а после 30 таких ошибок за 10 минут с одного IP `/setup` и вебхук для этого IP закрываются. Тело запроса ограничено (8 КБ для приложения, 1 МБ для вебхука), initData — 4 КБ. Лимиты на пользователя Telegram лежат в `LIMITS`: 60 запросов состояния и 20 действий в минуту; кто продолжает слать запросы сверх лимита (20 отказов за 10 минут), получает блокировку на 30 минут — она хранится в таблице `blocks` и действует во всех экземплярах воркера. Ещё: не больше 3 активных броней игровой на человека и 6 броней или отмен за 10 минут (админов не касается), не больше 5 уведомлений от одного человека другому в час (лишние не отправляются, само действие проходит), не больше 5 команд в минуту в личке. Команды в группе (`/board`, `/playroom` и модерация) принимаются только от админов чата, в том числе анонимных. Модерация: `/block` ответом на сообщение, `/block @username` или `/block id`, можно со сроком (`30m`, `12h`, `3d`) — закрывает доступ к приложению в этом чате и снимает очередь и брони; `/unblock` возвращает доступ, `/blocked` показывает список. Счётчики лимитов живут в памяти экземпляра воркера, поэтому от объёмного DDoS защищает сама сеть Cloudflare. В тестах лимиты запросов умножаются на `RATE_LIMIT_SCALE` из `tests/wrangler.toml`.

Страница приложения отдаётся статикой. `webapp/` подключён как `[assets]` в `wrangler.toml`, поэтому `GET /` обслуживает CDN Cloudflare, не запуская воркер: такие запросы бесплатны и не идут в счёт суточного лимита (100 000 запросов в день на бесплатном плане). Воркер запускается только на `/api/*`, `/telegram`, `/setup` и неизвестных путях. Заголовки безопасности для страницы — в `webapp/_headers`.

Чтобы флуд по `/api/*` не съедал суточный лимит, нужен свой домен (бесплатный можно получить на nic.eu.org) и бесплатное правило Rate limiting. Подключите воркер к домену (в `wrangler.toml` добавьте `routes = [{ pattern = "bot.example.org", custom_domain = true }]` и задеплойте), затем в дашборде Cloudflare: Security → WAF → Rate limiting rules → создайте правило с выражением `URI Path contains /api/`, порогом вроде 20 запросов за 10 секунд с одного IP и действием Block. Бесплатный план даёт одно такое правило (поля — только Path и Verified Bot, окно 10 секунд, счёт по IP). Автоматическая защита Cloudflare от DDoS на сетевом уровне работает на любом плане. Правила Rate limiting на адресе `*.workers.dev` не работают — только на своём домене; отключите `workers.dev` после перехода, иначе флуд пойдёт по нему.
