# Техэтаж

**Telegram-бот с мини-приложением для прачечной на техэтаже общаги**

Видно, какие стиралки и сушилки свободны, кто стирает и когда закончит.<br/>
Бот сам напомнит забрать вещи, позовёт, когда подошла очередь, и не даст чужим вещам пролежать в машине до утра.

## Как устроено

```mermaid
flowchart LR
    TG["Telegram"] -- "вебхук /telegram" --> W
    APP["Мини-приложение<br/>и сайт"] -- "/api/*" --> W
    APP -. "без VPN" .-> YC["Yandex Cloud<br/>API Gateway"]
    YC -. "/api/* + X-Relay-Key" .-> W
    CRON["Cron<br/>раз в минуту"] -- "tick()" --> W
    W["Cloudflare Worker<br/>src/worker.js"] <--> DB[("D1")]
    W -- "сообщения, закреп" --> TG
    CDN["CDN Cloudflare<br/>webapp/"] -- "GET /" --> APP
```

- **Весь сервер** находится в [`src/worker.js`](src/worker.js). Он принимает вебхук Telegram (`/telegram`), отдаёт страницу приложения ([`webapp/index.html`](webapp/index.html)) и обрабатывает её запросы (`/api/state`, `/api/action`).
- **Пользователь** проверяется по подписи Telegram.
- **Cron** раз в минуту вызывает `tick()`: напоминания, конец программ, брони, обновление закрепа. Запросы приложения вызывают `tick()` только по своему чату и выходят сразу, если делать нечего, поэтому опрос состояния стоит три обращения к базе.
- **Нажатия кнопок** приходят тем же вебхуком как `callback_query`.
- **Таблицы** в базе создаются сами, а настройки лежат константами в начале `src/worker.js`.
- **Страница приложения отдаётся статикой.** `webapp/` подключён как `[assets]` в `wrangler.toml`, поэтому `GET /` обслуживает CDN Cloudflare без запуска воркера. Такие запросы бесплатны и не идут в суточный лимит (100 000 запросов в день на бесплатном плане). Воркер запускается только на `/api/*`, `/telegram`, `/setup` и неизвестных путях. Заголовки безопасности для страницы лежат в [`webapp/_headers`](webapp/_headers).

## Деплой

```bash
npm install
npx wrangler login

npx wrangler secret put BOT_TOKEN
npx wrangler secret put WEBHOOK_SECRET
npx wrangler secret put RELAY_KEY

npm run deploy
```

Потом:

1. Откройте **`/setup?key=WEBHOOK_SECRET`** на адресе воркера. Без этого шага Telegram не будет присылать нажатия кнопок. `/setup` регистрирует вебхук и меню команд (в том числе `/login`) и показывает адрес мини-приложения.
2. В **@BotFather**: `/myapps` → приложение → *Edit Web App URL* → `https://…workers.dev/start`.
3. Сделайте бота **админом** общего чата и отправьте **`/board`** в теме прачечной.

> [!IMPORTANT]
> Секреты задаются только в Cloudflare. В репозиторий их не кладём.

`npm run build` собирает `dist/worker.js`: один файл без импортов, в котором страница и загрузчик встроены строками.

## Настройки

**Секреты** (`npx wrangler secret put …`)

| Секрет | Зачем |
|---|---|
| `BOT_TOKEN` | Токен бота от @BotFather |
| `WEBHOOK_SECRET` | Проверка вебхука Telegram и ключ для `/setup` |
| `RELAY_KEY` | Ключ шлюза Yandex Cloud, см. [Работа без VPN](#работа-без-vpn) |

**Переменные** (`[vars]` в [`wrangler.toml`](wrangler.toml))

| Переменная | Что задаёт |
|---|---|
| `ALLOWED_CHATS` | id чатов, где работает бот, через запятую или пробел (`-100…` у супергрупп). Если пусто, ограничения нет |
| `OWNER_ID` | Кому приходят сообщения `/problem` |
| `SITE_URL` | Адрес сайта для ссылок `/login` (сейчас адрес шлюза) |
| `APP_SHORT_NAME` | Короткое имя мини-приложения для ссылок `t.me/…/<имя>?startapp=…` |
| `TZ_NAME` | Часовой пояс, по умолчанию `Asia/Yekaterinburg` |
| `LAUNDRY` | `on` / `off`, прачечная |
| `PLAYROOM` | `on` / `off`, игровая |
| `ROOM_REMIND_HOUR` | Час вечернего вопроса про брони игровой |

Остальные настройки (лимиты, тайминги, тексты) лежат **константами в начале [`src/worker.js`](src/worker.js)**: `WARN_MINUTES`, `MAX_MINUTES`, `NAG_HOURS`, `DIGEST_HOUR`, `LIMITS`, `HINTS` и другие.

## Тесты

Тесты в [`tests/`](tests/) работают с **фейковым Telegram**:

```bash
npm test            # или: python tests/all.py
```

Каждый прогон заново поднимает фейковый Telegram и воркер, гоняет все наборы и гасит оба (логи в `tests/faketg.log` и `tests/server.log`). Поднимать заново приходится потому, что лимиты уведомлений живут в памяти воркера, и повторный прогон упёрся бы в них.

Чтобы гонять один набор, запустите в отдельных терминалах `python tests/faketg.py` и `npm run test:server`. Наборы можно запускать по одному и в любом порядке:

| Набор | Что проверяет |
|---|---|
| `drive.py` | брони, очередь, время |
| `done.py` | конец программы, забытые вещи |
| `room.py` | игровая |
| `auth.py` | подпись initData, секрет вебхука, права админа |
| `race.py` | параллельные запросы и перекладывание в выбранную машину |
| `abuse.py` | лимиты, флуд, размер запросов, `/block` |
| `web.py` | вход на сайте |
| `habits.py` | напоминания с кнопками, вечерняя сводка, значки, подсказки в чате |
| `common.py` | общая обвязка: подписанный initData, вызов вебхука, запуск cron, доступ к базе |

## Подробно о функциях

### Исправление времени

Машина может пересчитать время по ходу программы, поэтому у работающей машины есть кнопка **«Время на дисплее другое»**. Часы и минуты, которые сейчас показывает дисплей, выбираются прокруткой (часы 0–5, минуты 00–59), так что больше `MAX_MINUTES` выставить нельзя. Исправить может любой, кто стоит у машины.

**Лимиты** (в начале `src/worker.js`):
- каждый человек исправляет время на одной программе **один раз**, всего не больше `TIMER_EDITS` (3) человек за программу;
- **сократить** время можно сколько угодно: машина с датчиком влажности может закончить намного раньше;
- **продлить** можно не дальше `TIMER_SHIFT_MINUTES` (60 мин) от изначально введённого конца; вся программа не длиннее `MAX_MINUTES`;
- закончившую программу продлить нельзя;
- лимиты хранятся в строке машины и обнуляются, когда в ней запускают новую программу («Занять» или «Запустить программу»), а не по времени.

**Исключения.** Тот, кто запустил программу (а если машину отметили за другого, то тот, кто отметил), исправляет без ограничения по числу правок, чтобы мог вернуть неверную правку. Админ чата правит без ограничений.

**Прозрачность.** Все видят, что время исправляли, кто сделал это последним и каким время было изначально. Хозяину вещей, тому, кто забронировал машину после программы, и тому, чью бронь задевает новое время, приходит уведомление с именем исправившего. Правка пишется в `events` как `retime`. Если после правки до конца остаётся больше `WARN_MINUTES` (15 мин), предупреждение «скоро закончит» придёт ещё раз по новому времени (в общем чате правится то же сообщение). Кто исправляет время во вред, того админ может закрыть командой `/block`.

### Уведомления и общий чат

- Уведомления о стирке бот шлёт **в личку**.
- В общий чат (в тему закрепа) идёт только предупреждение **«скоро закончит»**, когда хозяин вещей не отмечен или его личка закрыта.
- Когда программа заканчивается, бот **правит то же предупреждение** на «закончила», а не пишет новое. На одну программу в чате одно сообщение, его id хранится в `machines.warn_msg`.
- Если личка хозяина закрыта, а предупреждения не было (короткая программа), бот пишет в чат в конце программы.
- Хозяина с закрытой личкой бот **тегает и объясняет почему**: «Стиралка 3 закончила. @username, у тебя закрыты личные сообщения — забери, пожалуйста, вещи.» (для «скоро закончит»: «…поэтому напоминаю здесь»). Другого способа достучаться до него у бота нет, иначе вещи так и пролежат. Если к концу программы личка открылась, сообщение правится на просто «закончила» без тега.
- **«Вещи забраны»** на машине с оставленными вещами («готово», вещи без программы, переложенные вещи) может нажать любой, и хозяину вещей приходит уведомление, кто это сделал.

### Напоминания забрать вещи

Сообщение «закончила» в личке приходит с кнопками **«Вещи забраны»**, **«Через 15 мин»** и **«Можно переложить»**.

- Если вещи так и лежат, бот напоминает хозяину через `NAG_HOURS` (**1, 3 и 5 ч**) после конца программы. На 5 ч приходит одна из нескольких шутливых фраз, не та же, что в прошлый раз (последняя хранится в `meta` как `nag:<id>`). Если до напоминания прошло несколько ступеней сразу (например, бот был выключен), приходит только последняя.
- **«Через 15 мин»** откладывает напоминание (`SNOOZE_MINUTES`) не больше `SNOOZE_MAX` (2) раз. Автоосвобождение через `CLOTHES_HOURS` при этом не сдвигается.
- **«Можно переложить»** прекращает напоминания хозяину, пишет тому, кто забронировал машину после программы, и первому в очереди, а в приложении на машине появляется «Хозяин разрешил переложить вещи».
- Кнопки привязаны к программе (`started_at`), поэтому в старых сообщениях не срабатывают. Нажать их может только хозяин вещей.
- На 5 ч, если машину кто-то ждёт (очередь или бронь после программы), в общий чат идёт сообщение **«Хозяин, отзовись»** без имени хозяина (правится то же сообщение `warn_msg`, отметка `called`). Когда вещи забрали или переложили, оно правится на «освободилась» или «переложили в …».
- Ступень, отложенное время и отметки хранятся в строке машины: `nag`, `snooze_until`, `snoozes`, `movable`, `called`.

### Вечерняя сводка

Включается **только по желанию**: галочкой «Вечерняя сводка» в приложении или кнопкой «Да, присылай». Бот один раз предлагает сводку после того, как человек сам нажал «Вещи забраны» на своей машине.

- В `DIGEST_HOUR` (20:00) бот присылает в личку, какие машины свободны, какая освободится первой, когда обычно наплыв (`PEAK_HOURS`) и что спокойнее всего в `QUIET_HOURS` (с 2 до 10).
- Получают только те, кто открывал приложение за последние `DIGEST_ACTIVE_DAYS` (14) дней и не заблокирован.
- Не чаще раза в день (`people.digest_day`) и не больше `DIGEST_BATCH` сообщений за запуск таймера, чтобы не упереться в лимит подзапросов бесплатного плана.
- Под сводкой есть кнопка «Отписаться». Значков и рейтингов в сводке нет.

### Значки и доска почёта

Видны **только в приложении** (карточка «Доска почёта»). Бот не пишет о них ни в личку, ни в чат, и никаких преимуществ они не дают. Всё считается по таблице `events`.

| Значок | Условие за неделю |
|---|---|
| **Молния** | 3 раза забрать свои вещи в первые `LIGHTNING_MINUTES` (10) минут после конца программы |
| **Герой прачечной** | 2 отметки чужой стирки («Не мои, просто отмечаю») или вещей без программы. Не больше одной на машину в день и не больше `HERO_WEEK_CAP` (5) в зачёт. Отметки, которые сам отметивший или админ снял в течение `HERO_REVERT_MINUTES` (30) минут, не считаются |
| **Сова** | 2 стирки, запущенные с 2 до 10 утра |
| **Чистая неделя** | Минимум 2 стирки, и все вещи забраны в течение часа |

- Неделя начинается с понедельника. В понедельник после часа ночи таймер записывает значки прошлой недели в таблицу `badges` (отметка `badges_week` в `meta`).
- Доска почёта показывает **топ-3 прошлой недели** по каждому значку, кроме «Чистой недели», с общими местами при равенстве.
- Свой прогресс за текущую неделю считается при открытии карточки (`GET /api/honor`).
- Кто включил «Не показывать моё имя», на доске значится как «Аноним».

### Статус в личке

Кому лень открывать приложение, отправляет боту в личку **`/status`** и получает сводку:

- сколько стиралок и сушилок свободно и какие именно;
- какие работают и до скольки (если свободных нет, то когда закончит ближайшая);
- в каких лежат вещи, какие придержаны для очереди или брони, какие сломаны, сколько человек в очереди;
- блок **«Твоё»**: свои машины с оставшимся временем, место в очереди, брони и переложенные вещи (на гладильной доске, в пакете или на какой-то машине).

Имён других людей в сводке нет. Чат определяется сам: бот берёт чат с закрепом прачечной, где состоит человек (если таких несколько, то тот, где он последним открывал приложение). Не участникам бот отвечает, что прачечной не нашёл, а тем, кому закрыт доступ, объясняет почему. Под сводкой есть кнопка «Открыть прачечную», за свежим статусом нужно снова отправить `/status`. В группе `/status` просто удаляется. Пока прачечная выключена (`LAUNDRY = "off"`), команды нет.

### Сайт

То же приложение открывается в обычном браузере по адресу воркера (`https://…workers.dev/` или свой домен): та же страница `webapp/index.html` и те же `/api/state` и `/api/action`.

**Вход только через бота:**
1. `/login` в личке (или кнопка «Получить ссылку в Telegram» на сайте, она открывает бота с `/start login`) присылает кнопку со ссылкой `/#login=…`.
2. Ссылка одноразовая и живёт `LOGIN_MINUTES` (10 мин). Токен стоит после `#`, поэтому не уходит на сервер, когда Telegram или браузер подгружают превью.
3. Страница меняет токен через `POST /api/login` на cookie `session` (HttpOnly, SameSite=Strict, Path=/api) на `SESSION_DAYS` (30 дней).

**Безопасность:**
- В таблице `sessions` лежат только SHA-256 хеши токенов.
- Вход со страницы чужого сайта (заголовок Origin) отклоняется. Неверные ссылки и cookie идут в тот же лимит ошибок по IP, что и неверный initData.
- Участие в чате, блокировки и лимиты проверяются на каждом запросе, как в Telegram, поэтому `/block` закрывает и сайт.
- Кнопка «Выйти» внизу страницы удаляет сессию (`POST /api/logout`).
- Если запрос несёт и initData, и cookie, используется initData.

Чат выбирается так же, как для `/status`. Ссылка строится от адреса, на который Telegram шлёт вебхук; другой адрес сайта задаётся переменной `SITE_URL`. Без темы Telegram сайт берёт светлую или тёмную тему системы. После деплоя откройте `/setup?key=WEBHOOK_SECRET`, чтобы `/login` появилась в меню команд бота.

### Сообщения о проблемах

- В личке с ботом `/problem текст` или `/problem` с ответом на вопрос бота (можно со скриншотом) пересылается в личку пользователю с id из `OWNER_ID`, вместе с именем и id отправителя.
- Владелец должен сам нажать «Старт» у бота, иначе Telegram не даст боту ему писать. Без `OWNER_ID` бот отвечает, что передать некому.
- Принимаются текст, фото, картинки JPG, PNG и WebP, PDF и видео MP4 до 20 МБ (`PROBLEM_FILES`, `PROBLEM_FILE_MB`). На другой формат или слишком большой файл бот объясняет, что не так, и снова просит описать проблему. Такие попытки не тратят лимит сообщений о проблемах.
- **Ответ владельца:** Reply на сообщение «Проблема от …». Бот пересылает ответ (можно со скриншотом) и пишет «Отправлено.» или «Не доставлено». Человек может ответить на ответ, и это снова придёт владельцу как «Проблема от …». Отвечать так может только пользователь с `OWNER_ID`.

### Подсказки в чате

Кто пишет в общий чат словами вместо приложения, тому бот отвечает (Reply) подсказкой с кнопкой **«Отметить в приложении»**. Правила лежат в `HINTS` в `src/worker.js`.

| Подсказка | Когда срабатывает | Примеры |
|---|---|---|
| **«Переложил чужие вещи?»** | Текст или подпись к фото со словом на «перелож», «перекин», «вытащ», «вынул» (`MOVE_WORDS`) в любом роде и числе | Да: «переложила», «перекинули», «вещи переложены» |
| **«Стирка закончилась?»** | Короткое сообщение (до 6 слов, без «?») со словом «все»/«всё» или «закончил…»/«постирал…» (`DONE_WORD`), где остальные слова — номера машин, «стиралка», «сушилка», «машина», «стирка», «сушка» в любой форме или связки из `DONE_FILLER` («уже», «тоже», «у меня», «моя»…) | Да: «5 всё», «стиралка 3 закончила», «у меня постиралось»<br/>Нет: «все заняты», «всё?», «порошок закончился» |

- Каждого вида не больше одной подсказки в чат за 10 минут (лимит `hint` в `LIMITS`).
- Кнопка открывает приложение со ссылкой `startapp=<чат>_<вид><id сообщения>` (`m` значит «переложил», `f` значит «закончилась»). Приложение по такой ссылке показывает сверху карточку, что нажать. Карточка пропадает после нужного действия или по «Скрыть».
- **Подсказка удаляется**, когда приложение по кнопке открывает любой участник чата. Telegram не сообщает боту о нажатии кнопки-ссылки, поэтому сигналом служит первый запрос приложения с такой ссылкой.
- id подсказок хранятся в таблице `hints` и стираются через `HINT_HOURS` (48 ч). Позже Telegram не даёт боту удалять свои сообщения, поэтому подсказка, по которой никто не открыл приложение, остаётся в чате.
- Бот реагирует только на новые сообщения: старые и отредактированные не проверяются.

> [!NOTE]
> Чтобы видеть обычные сообщения группы, бот должен быть админом чата (он им и так является ради закрепа) или иметь выключенный privacy mode в @BotFather.

## Защита от флуда и нарушителей

**До базы.** Запросы без верной подписи Telegram отсекаются до обращения к базе: неверный initData, секрет вебхука или ключ `/setup` стоят только проверки HMAC (сравнение за постоянное время). После 30 таких ошибок за 10 минут с одного IP `/setup` и вебхук для этого IP закрываются.

**Размеры.** Тело запроса ограничено: 8 КБ для приложения, 1 МБ для вебхука; initData не больше 4 КБ.

**Лимиты** на пользователя Telegram лежат в `LIMITS`:

| Что | Лимит |
|---|---|
| Запросы состояния | 60 в минуту |
| Действия | 20 в минуту |
| Флуд сверх лимита | 20 отказов за 10 минут → блок на 30 минут (таблица `blocks`, действует во всех экземплярах воркера) |
| Уведомления от одного человека другому | 5 в час (лишние не отправляются, само действие проходит) |
| Команды в личке | 5 в минуту |
| Сообщения о проблемах | 5 в час |

**Модерация** (только админы чата, в том числе анонимные):
- `/block` ответом на сообщение, `/block @username` или `/block id`, можно со сроком (`30m`, `12h`, `3d`). Закрывает доступ к приложению в этом чате и снимает очередь и брони.
- `/unblock` возвращает доступ, `/blocked` показывает список.
- `/unpin` убирает закреплённые сообщения бота из темы, где отправлена команда, `/unpin all` из всего чата. Закреп больше не обновляется, а если в чате не осталось ни одного, приложение не откроется, пока админ снова не отправит `/board`.

**Только свой чат.** Бот работает только в чатах из `ALLOWED_CHATS`.
- Если бота добавить в любой другой чат, он пишет, что работает только в чате общаги, и сразу выходит. На команды из такого чата тоже отвечает выходом, а приложение по ссылке с id чужого чата не открывается.
- Каждая такая попытка записывается в `events` с действием `foreign` (кто добавил, название чата).
- `/setup` снимает закрепы бота в чужих чатах, выходит из них и показывает список разрешённых чатов. Если `ALLOWED_CHATS` пуст, ограничения нет, а `/setup` показывает id чатов, где сейчас есть закреп.
- Добавлять бота в группы можно запретить и в @BotFather (*Bot Settings → Allow Groups? → Turn groups off*). Из уже добавленных чатов он при этом не выходит.

> [!WARNING]
> Обычная группа при превращении в супергруппу меняет id. Новый id нужно добавить в `ALLOWED_CHATS` заранее, иначе бот из неё выйдет.

Счётчики лимитов живут в памяти экземпляра воркера, поэтому от объёмного DDoS защищает сама сеть Cloudflare.

## Бесплатный план и свой домен

Чтобы флуд по `/api/*` не съедал суточный лимит, нужен свой домен (бесплатный можно получить на nic.eu.org) и бесплатное правило Rate limiting:

1. Подключите воркер к домену: в `wrangler.toml` добавьте
   ```toml
   routes = [{ pattern = "bot.example.org", custom_domain = true }]
   ```
   и задеплойте.
2. В дашборде Cloudflare: *Security → WAF → Rate limiting rules* → правило с выражением `URI Path contains /api/`, порогом вроде 20 запросов за 10 секунд с одного IP и действием *Block*.

Бесплатный план даёт одно такое правило (поля только Path и Verified Bot, окно 10 секунд, счёт по IP). Автоматическая защита Cloudflare от DDoS на сетевом уровне работает на любом плане.

> [!CAUTION]
> Правила Rate limiting на адресе `*.workers.dev` не работают, только на своём домене. Отключите `workers.dev` после перехода, иначе флуд пойдёт через него.

## Работа без VPN

**Проблема.** Российские провайдеры режут соединения с Cloudflare после первых ~16 КБ, а прокси для Telegram окно мини-приложения не использует. Поэтому без VPN страница с `*.workers.dev` не загружается.

**Решение в два слоя:**

1. **Yandex Cloud API Gateway** (бесплатно до 100 000 запросов в месяц) стоит перед воркером: отдаёт `/` и пересылает `/api/*` на воркер. Вебхук Telegram, cron и база остаются в Cloudflare.
2. **Загрузчик `/start`** ([`src/start.html`](src/start.html), ~3 КБ, меньше порога обрыва). С некоторых VPN (например, эстонских) не открывается уже Яндекс, поэтому загрузчик качает страницу приложения одновременно с воркера и со шлюза, показывает ту, что пришла первой целиком, и все запросы `/api/*` приложение шлёт туда же.

| Сеть | Кто выигрывает |
|---|---|
| Без VPN | шлюз |
| С VPN | любой |
| С эстонским VPN | воркер |

**Детали:**
- Адрес Mini App для BotFather (*/myapps → приложение → Edit Web App URL*) — `https://…workers.dev/start`, его показывает `/setup`.
- Адрес шлюза записан в `SITE_URL`. На него ведут ссылки `/login` (сайт ходит только на свой адрес, потому что вход держится на cookie), и его загрузчик пробует вторым.
- Запросы со страницы воркера на шлюз идут с другого адреса, поэтому в спецификации шлюза включён CORS для адреса воркера.
- Все пользователи для воркера приходят с IP шлюза, поэтому шлюз добавляет заголовок `X-Relay-Key` с секретом `RELAY_KEY`. Только с верным ключом воркер берёт IP посетителя из последнего адреса в `X-Real-Remote-Address`: его дописывает сам шлюз, подделать его нельзя. Без этого 30 неверных запросов одного человека закрыли бы вход всем.
- Вход на сайт принимает Origin и воркера, и `SITE_URL`. Старый адрес `workers.dev` продолжает работать с VPN.

<details>
<summary><b>Спецификация шлюза</b> (подставьте свой <code>RELAY_KEY</code>)</summary>

```yaml
openapi: 3.0.0
info:
  title: techfloor
  version: 1.0.0
x-yc-apigateway:
  cors:
    origin: https://techfloor.lanhua1122333.workers.dev
    methods: [GET, POST]
    allowedHeaders: [Content-Type, X-Init-Data]
    maxAge: 600
paths:
  /:
    get:
      x-yc-apigateway-integration:
        type: http
        url: https://techfloor.lanhua1122333.workers.dev/
  /api/{path+}:
    x-yc-apigateway-any-method:
      parameters:
        - name: path
          in: path
          required: true
          schema:
            type: string
      x-yc-apigateway-integration:
        type: http
        url: https://techfloor.lanhua1122333.workers.dev/api/{path}
        headers:
          '*': '*'
          Host: techfloor.lanhua1122333.workers.dev
          X-Relay-Key: RELAY_KEY
        timeouts:
          connect: 5
          read: 25
```

`Host` нужно задать явно: с `'*': '*'` шлюз иначе передаёт свой адрес, и Cloudflare обрывает TLS-соединение.

</details>

## Игровая (в архиве)

Календарь броней игровой сейчас **выключен**: код остаётся в `src/worker.js` и `webapp/index.html`, но в продакшене его не видно.

**Как включить:** `PLAYROOM = "on"` в `[vars]` в `wrangler.toml` (сейчас `"off"`, без переменной игровая тоже выключена), затем `npm run deploy` и `/setup?key=WEBHOOK_SECRET`, чтобы вернуть описание бота и команду `/playroom` в меню.

**Пока игровая выключена:**
- нет вкладки и календаря в приложении;
- команда `/playroom` и кнопки из старых личных сообщений игнорируются, действия `room_*` отклоняются;
- cron не шлёт напоминания о бронях и не обновляет закреп игровой;
- `/start`, описание бота и меню команд говорят только про прачечную;
- таблицы `pboards`, `room_bookings`, `room_joins`, `room_requests` и данные в них не трогаются;
- старый закреп игровой в чате остаётся как есть. Его можно убрать командой `/unpin` в теме игровой; кнопка в нём открывает прачечную.

<details>
<summary><b>Как работает игровая</b></summary>
<br/>

- **Брони.** Бронь бывает закрытой (просто занято) или **открытым событием**: его анонсируют в чате, любой участник может нажать «Я приду», а в приложении и в закрепе видно, сколько людей идёт.
- **Места.** Организатор может ограничить число мест (от 1 до 100, сам организатор не в счёт) или оставить событие без ограничения. Когда места кончаются, кнопка «Я приду» сменяется на «Мест нет».
- **Правка.** Свою бронь можно изменить (время, повод, открытая или закрытая, число мест). Правка анонсируется в чате, при переносе записавшимся приходит сообщение, а если событие стало закрытым, записи снимаются. Перед бронью и правкой приложение показывает сводку «Всё верно?».
- **Напоминания.** Cron вечером (`ROOM_REMIND_HOUR`) спрашивает в личке про брони на завтра кнопками «Да, бронь нужна» / «Нет, отменить бронь» и напоминает за полчаса до начала. Записавшимся на открытое событие (таблица `room_joins`) тоже приходит напоминание за полчаса с кнопкой «Не приду», а если событие отменят, приходит сообщение об отмене.
- **Заявки.** К закрытой брони можно попроситься кнопкой «Попроситься» (можно с коротким сообщением). Заявка (таблица `room_requests`) приходит организатору в личку с кнопками «Принять» / «Отказать»; если личка закрыта, бот упоминает его в теме игровой. Заявки видны организатору в приложении в блоке «Просятся к тебе».
  - Принятый гость попадает в `room_joins` и получает те же напоминания и сообщения о переносе и отмене, что и записавшиеся на событие.
  - После отказа попроситься в ту же бронь снова нельзя, а заявку до ответа можно отозвать.
  - Организатор видит настоящее имя того, кто просится, даже если оно скрыто.
  - Если закрытая бронь стала открытым событием, заявки снимаются, и просившимся приходит сообщение, что можно просто нажать «Я приду».
  - Не больше 10 заявок в час на человека.
- **Лимиты.** Не больше 3 активных броней на человека и 6 броней или отмен за 10 минут (админов это не касается).
- Админ закрепляет игровую командой `/playroom` в нужной теме. `/block` снимает и будущие брони игровой.

</details>

## Выключение прачечной

Прачечная выключается так же: `LAUNDRY = "off"` в `[vars]` в `wrangler.toml` (сейчас `"on"`, без переменной прачечная включена), затем `npm run deploy` и `/setup?key=WEBHOOK_SECRET`, чтобы обновить описание бота и меню команд.

**Пока прачечная выключена:**
- нет вкладки прачечной, приложение сразу открывает игровую;
- команда `/board` игнорируется, действия прачечной отклоняются;
- cron не обрабатывает машины, очередь и брони и не обновляет закреп прачечной;
- `/start`, описание бота и меню команд говорят только про игровую;
- таблицы прачечной и данные в них не трогаются;
- старый закреп прачечной в чате остаётся как есть. Его можно убрать командой `/unpin` в теме прачечной; кнопка в нём открывает игровую.

Если выключить и прачечную, и игровую, приложение отвечает «Приложение сейчас выключено».
